# Project Architecture & Policy (beep-gen)

## 1. 프로젝트 개요
- **목적**: 사용자가 지정한 주기(n초), 비트 분할(m개), 약한 비프 볼륨 비율, 전체 길이(l초), TTS 인트로 안내를 포함하는 맞춤형 비프음 오디오 생성기. 향후 음악 파일의 템포를 비프에 맞춰 변환하는 기능을 포함한다.
- **대상 환경**: 웹(GitHub Pages, PWA) + PC 로컬앱(Tauri 2) + CLI·로컬 MCP. 모바일은 PWA만 지원하며 스토어 앱은 만들지 않는다.
- **현행(레거시)**: Python 3.12 + PyQt6 + FFmpeg (`main.py`, `gui.py`, `generator.py`, `tts_engine.py`). Rust 버전이 동일 기능에 도달할 때까지 유지하며, 제거 여부는 그때 사용자에게 확인한다.

## 2. 멀티 플랫폼 아키텍처 (2026-11-13 사용자 확정)

### 2.1 원칙: UI 1벌, 코어 1벌, 환경별 어댑터만 교체
- **코어(Rust)**: 비프 합성, 디코딩, 박자 분석, 템포 변환, 이어 붙이기, MP3/WAV 인코딩을 모두 담는다. 웹은 WASM, 로컬은 네이티브로 같은 코드를 컴파일한다.
- **UI(TypeScript)**: 화면 코드는 하나이며 웹과 로컬앱이 공유한다.
- **어댑터**: 환경마다 달라지는 것은 음성 합성(TTS), 음악 입력(파일/URL), 결과 저장뿐이다.

### 2.2 강제 규칙
1. **코어에 플랫폼 코드 금지**: 코어는 파일·네트워크·시계·OS 호출을 직접 쓰지 않는다. CI에서 코어를 항상 `wasm32-unknown-unknown`으로도 빌드해 검증한다.
2. **어댑터에 계산 로직 금지**: 어댑터는 가져오기·내보내기·OS 호출만 한다. 오디오 샘플을 건드리는 코드는 반드시 코어에 둔다.
3. **UI는 기능 지원 여부로 분기**: "데스크톱이면"이 아니라 "TTS를 지원하면"으로 판단한다. 환경 이름으로 분기하지 않는다.
4. **파라미터 정의는 코어 한 곳**: `n`, `m`, 볼륨, 길이 등의 이름·기본값·범위는 코어의 구조체 하나에 정의하고 UI 타입, CLI 옵션, MCP 도구 스키마는 거기서 파생한다.
5. **C/C++ 의존성 금지**: WASM 빌드를 깨뜨리므로 순수 Rust 라이브러리만 쓴다. 시스템 FFmpeg에도 의존하지 않는다.
6. **웹·로컬 결과 검증은 특성 비교로**: 템포 변환 결과는 양쪽이 샘플 단위로 일치하지 않으므로(검증에서 확인) 길이·박 위치·검출 BPM 같은 특성으로 비교한다.

### 2.3 사용 라이브러리 (모두 순수 Rust)
- 템포 변환 + 박자 분석: `timestretch` (MIT). 0.x 버전이라 올릴 때 API 변경을 확인한다.
- MP3 인코딩: `rusty_mp3` (Apache-2.0)
- 음악 디코딩(MP3·WAV·FLAC·OGG·M4A): `symphonia` (MPL-2.0)
- 수학 함수: `libm`. 웹과 로컬의 결과가 달라지지 않도록 표준 `sin`/`cos` 대신 쓴다.

### 2.4 배경 음악 정책 (2026-11-13 사용자 확정)
- **비프와 음악은 겹친다.** 비프 음량(`beep-volume`)과 음악 음량(`music-volume`)을 각각 0~100%로 조절한다. 비프 음량 0이면 템포만 맞춘 음악이 된다.
- **기본 음량은 비프 30%, 음악 100%**(2026-11-15 사용자 의견 반영: 비프가 너무 크고 음악이 작았다). 비프는 한 음높이의 또렷한 소리라 같은 크기여도 훨씬 크게 들린다. 비프 음량은 음악과의 균형을 잡는 값이므로 음악이 없을 때는 쓰지 않는다(비프만 있는 음원은 늘 제 크기).
- **음원 길이는 음악 길이를 따른다.** 길이(`length`)는 음악이 없을 때만 쓴다. 음악을 자르거나 반복하지 않는다.
- **음악의 앞부분을 자르지 않는다.** 비프 격자를 음악의 기준 박(마디 시작, 불확실하면 첫 박)에 맞춰 옮긴다.
- **두 소리의 최대 진폭 합이 1을 넘으면 넘는 만큼 둘 다 줄인다**(찌그러짐 방지).
- **템포 변환 폭은 제한하지 않고 경고한다.** 한 박을 비프 간격의 0.5·1·2배 중 가장 가까운 쪽에 맞추므로 변화는 최대 약 ±41%이며, 15%를 넘으면 음질 저하를 경고한다.
- 박자를 찾지 못한 곡은 오류로 거절한다. 템포가 변하는 곡은 박마다 따라가 맞추고(2.5절), 변화가 1.5%를 넘으면 구간에 따라 음높이가 조금 달라질 수 있다고 알린다.

### 2.5 박자 정렬 규칙 (검증에서 도출)
- **곡 전체를 한 가지 템포로 보지 않는다**(2026-11-15 수정). 사람이 연주한 곡은 템포가 흔들려서, 한 배율로만 늘이면 뒤로 갈수록 어긋난다(템포가 2%만 변해도 4분 곡에서 ±270ms). 검출한 박 하나하나를 비프 격자의 제자리로 보내는 박 지도(`beatmap.rs`)를 만들어 따라간다.
- **검출한 박을 그대로 믿지 않는다**(2026-11-15 추가). 검출기는 드럼이 약한 구간에서 반 박쯤 미끄러지곤 하고, 박 지도는 그 실수까지 따라간다(실제 곡에서 2분 지점부터 비프가 박 사이에 떨어진 사례). 그래서 먼저 소리 자체로 격자를 찾는다(`steady.rs`): 소리가 커지는 지점들을 박 간격으로 접어 겹쳐, 20초 구간마다 같은 자리에 몰리면 "템포가 일정한 곡"으로 보고 `첫 박 + k × 간격` 격자를 쓴다. 대부분의 대중음악이 여기에 든다.
- **3박 계열(3/4, 6/8 등)은 비프 세 개를 한 마디로 묶는다**(2026-11-15 사용자 확정). 검출기는 이런 곡의 맥박 두 개를 한 박으로 읽어서, 그대로 쓰면 비프의 강약이 곡의 강세와 세 번에 한 번만 만난다(실제 곡 사례: 98 BPM 으로 읽혔지만 강세는 65 BPM). `steady.rs` 가 맥박 세 개 간격의 강세가 두 개·네 개 간격보다 1.3배 넘게 또렷하면 3박 계열로 보고, 맥박 단위의 격자와 강세의 자리를 내준다. 고정 격자를 쓸 수 있는 곡에서만 한다. **비프 간격은 언제나 n/m 초다.** 3박 계열에서는 맥박 1·2·4개 중 템포를 가장 덜 바꾸는 쪽을 비프 하나에 맞추고, 비프 세 개가 한 마디가 되어 마디의 첫 비프가 곡의 강세에 온다. 한 마디의 강약은 `triple-accent` 로 고른다: 강약강(분할대로 강약을 놓고 마디마다 다시 시작. 2분할이면 처음 강에서 두 번째 강까지가 n 초) 또는 강약약(마디의 첫 비프만 강). 3분할 이상은 어느 쪽이든 강약약이 된다. 몇 분의 몇 박자인지(3/4 인지 6/8 인지)는 소리만으로 가릴 수 없어 2박 계열·3박 계열까지만 가린다. 분석이 틀렸으면 `meter`(0 자동, 2, 3)로 직접 정한다.
  - 구간 사이에서 자리가 박의 1/12(약 0.5% 템포 차이)보다 많이 움직이거나 또렷한 구간이 70% 미만이면 격자를 쓰지 않고 검출한 박을 따라간다.
  - 접어 겹친 자리는 편곡이 바뀔 때도(하이햇이 들어오는 등) 수십 ms 움직인다. 이것은 템포 변화가 아니므로, 구간별 움직임은 따라갔을 때 킥이 3% 이상 더 또렷하게 겹칠 때만 따라간다.
  - 정박과 엇박 중 어느 쪽이 박인지는 검출한 박이 많이 모인 쪽과 킥이 많이 떨어지는 쪽을 함께 보고 고른다.
  - 실제 곡으로 확인할 때는 `tools/check_phase.py`(구간별 위치)와 `dump_beats` 예제(판단에 쓴 값)를 쓴다.
- 평균 박 간격은 대표 BPM이 아니라 모든 박 위치에 대한 직선 맞춤으로 구한다. 이 값은 전체 템포 배율(음정을 유지하는 변환)을 정하는 데만 쓴다.
- 구간마다의 차이는 재샘플링으로 맞춘다. 변환 라이브러리가 "지금 낸 소리가 원곡의 어디까지인지"를 알려주므로, 그 위치가 박 지도에서 놓여야 할 자리까지 채우도록 구간마다 배율을 정한다. 모자라거나 넘친 만큼을 다음 구간에서 갚으므로 오차가 쌓이지 않는다. 라이브러리의 배율 반올림 오차도 여기서 함께 없어진다.
- 재샘플링은 음높이도 함께 바꾼다. 그래서 템포가 평균에서 벗어난 만큼(보통 1% 안팎) 구간별로 음높이가 달라진다. 한 구간에서 바꿀 수 있는 폭은 ±12%로 막아 둔다.
- 검출한 박은 ±10ms 안팎으로 흔들리므로 양옆 6박에 맞춘 직선으로 다듬는다. 템포가 바뀌는 경계는 넘겨 섞지 않는다. 검출이 박을 건너뛴 곳은 번호도 건너뛴다.
- 템포 변환·재샘플링·합치기·인코딩은 구간 단위로 이어서 처리한다. 변환된 음악 전체를 메모리에 쌓지 않는다(5분 곡 기준 WASM 메모리 약 170MB).
- 정렬 확인: `crates/beep-core/tests/music_alignment.rs`(자동, 템포가 변하는 곡 포함), `tools/check_align.py`(수동 측정), `cargo run --release -p beep-core --example dump_beats -- <곡>`(검출한 박 살펴보기).

## 3. 웹 UI 정책 (2026-11-13 사용자 확정)
- **CSS 스타일링 아키텍처**: 단일 중앙 집중형 CSS(`src/styles/app.css`). 컴포넌트별 CSS, CSS Modules, Tailwind는 쓰지 않는다.
- **이원화 버전 관리 및 캐시 버스팅**: 적용.
  - 빌드 태그 `YYYYMMDDvN`: `version.ts`에 두고, 웹에 반영되는 변경을 할 때마다 자동 갱신한다(같은 날 재변경 시 N 증가).
  - 정식 버전(SemVer): 사용자 승인 후에만 올린다.
- **호스팅**: GitHub Pages만 사용한다. 서버를 두지 않으며 모든 처리는 브라우저 안에서 한다.

### 3.1 웹 UI 구조와 빌드 (2026-11-13 구현)
- **위치**: 화면 코드는 `apps/web/`, 빌드 결과물은 저장소 루트 `dist/` (git 제외). `C:\git\open-test-server.bat` 가 `dist/index.html` 을 찾기 때문이다.
- **빌드 명령**: `apps/web` 에서 `npm.cmd run build` (WASM 생성 → 타입 검사 → 번들). 커밋 전 이 명령과 `cargo test --workspace --all-features` 가 모두 통과해야 한다.
- **경로는 상대 경로**: `vite.config.ts` 의 `base: "./"`. GitHub Pages(`/beep-gen/`)와 로컬 테스트 서버(`/beep-gen/`, `/beep-gen@브랜치/`)에서 같은 결과물이 동작해야 한다. 절대 경로(`/assets/...`)를 쓰지 않는다.
- **프레임워크 없음**: TypeScript + Vite 만 쓴다. 화면이 여러 개로 늘어나면 그때 사용자와 상의한다.
- **입력 폼은 코어의 명세로 생성**: 파라미터별 화면 코드를 따로 쓰지 않는다. 코어의 `param_specs()` 가 이름·기본값·범위를 알려주고 `main.ts` 가 그대로 그린다.
- **플랫폼 인터페이스**: 화면은 `src/platform.ts` 의 `Platform` 만 호출한다. 웹 구현은 `platform-web.ts`(워커 + WASM). 로컬앱은 같은 인터페이스의 다른 구현을 추가한다.
- **WASM 바인딩 생성**: `cargo run -p xtask -- wasm`. `crates/beep-wasm` 의 `wasm-bindgen` 과 `xtask` 의 `wasm-bindgen-cli-support` 는 반드시 같은 버전으로 고정한다. 생성물 `apps/web/src/wasm/` 은 git 에 올리지 않는다.
- **버전 파일**: `apps/web/src/version.ts`. `BUILD_TAG` 는 서비스 워커의 캐시 이름이며, `APP_VERSION` 이 Cargo 작업 공간 버전과 다르면 빌드가 실패한다.
- **빌드 표기 (2026-11-15 사용자 확정)**: 화면 위쪽과 제목표시줄에 `정식버전+빌드태그.빌드시각` 을 보여준다(예: `0.1.0+20261115v4.1115-1657`). 빌드 시각(`월일-시분`)은 `vite.config.ts` 가 빌드할 때마다 자동으로 넣는다. 커밋 전의 작업본을 시험할 때, 지금 보는 화면이 방금 빌드한 것인지 확인하는 용도다. 빌드한 뒤에는 이 표기를 사용자에게 알려준다.
- **PWA**: `public/sw.js` 가 빌드 때 만들어지는 `precache.json` 의 파일을 미리 캐시한다. `dist/` 를 통째로 비우지 않는다(`BeepGen.exe` 가 함께 있을 수 있음).

## 4. 로컬 기능 정책 (2026-11-13 사용자 확정)

### 4.1 TTS (시작 안내 음성)
- **로컬앱·CLI**: Windows 내장 음성만 쓴다(인터넷 불필요). Edge-TTS 등 온라인 엔진은 넣지 않는다. 다른 엔진을 추가할 때는 `beep-native::tts` 의 세 함수(`is_supported`, `list_voices`, `synthesize`) 모양을 유지한다.
- **웹**: 기본은 꺼져 있고, 원하는 사용자가 음성 모델을 내려받으면 브라우저 안에서 안내 음성을 만든다(2026-11-13 구현).
  - 모델은 Supertonic 2(약 264MB, 한국어·영어 등 5개 언어). 앱에 넣지 않고 사용자의 브라우저가 Hugging Face 에서 직접 받아 Cache Storage 에 보관한다. 받을 파일의 저장소 버전은 `apps/web/src/tts-model.ts` 에 고정한다.
  - 모델 라이선스(OpenRAIL-M)는 사용 조건을 사용자에게 알릴 의무가 있다. 내려받기 버튼 옆에 조건 요약과 전문 링크를 반드시 보여준다. 이 안내를 지우거나 자동으로 내려받게 바꾸지 않는다.
  - 내려받을 때 사용자의 접속 정보가 Hugging Face 에 전달된다는 점을 화면에 알린다. 문구와 음성은 기기 밖으로 나가지 않는다.
  - 휴대폰과 메모리가 적은 기기(4GB 미만)에서는 권하지 않고 로컬앱 안내만 보여준다.
  - 실행기는 `onnxruntime-web` 의 CPU(WASM) 판만 쓴다(약 15MB, 안내 음성을 쓰는 사람만 받도록 사전 캐시에서 제외). 합성은 별도 워커(`tts-worker.ts`)에서 한다.
- **안내 음성의 음량은 코어가 맞춘다**: 합성기마다 크기가 달라(웹 모델은 최대 진폭의 20% 수준) 코어가 최대 진폭 0.9 로 맞춘다.
- **음성을 만드는 일은 코어 밖**: 어댑터가 음성 파일(WAV)을 만들고, 코어는 그것을 받아 맨 앞에 넣은 뒤 0.5초 쉬고 비프를 시작한다. 문구의 `{n}`, `{m}`, `{l}` 치환은 코어의 `intro_text` 가 한다.
- **TTS 가 실패해도 음원은 만든다.** 대신 그 사실을 사용자에게 알린다(CLI 는 주의 문구, 앱은 결과 화면).

### 4.2 URL 로 음악 가져오기
- **오디오 파일의 직접 주소만 받는다**(예: `https://.../song.mp3`). 최대 200MB, 120초 제한.
- **YouTube 등 스트리밍 서비스 주소는 지원하지 않는다.** 저작권 문제 때문이며, 그런 주소가 들어오면 "필요하면 프로젝트를 포크해 직접 추가해 사용하라"는 안내와 함께 거절한다. 스트리밍 추출 기능을 이 저장소에 넣지 않는다.
- 웹에서는 브라우저 보안 정책(CORS) 때문에 제공하지 않는다. 로컬앱과 CLI 에서만 된다.

### 4.3 데스크톱 앱 구조 (2026-11-13 구현)
- **위치**: `apps/desktop/src-tauri` (Tauri 2). 화면은 `apps/web` 의 빌드 결과물(`dist/`)을 그대로 담는다. 화면 코드를 따로 두지 않는다.
- **로컬 어댑터**: `crates/beep-native` (TTS, URL 다운로드, 로컬 AI). CLI·데스크톱 앱·MCP 가 함께 쓴다. 여기에도 오디오 계산은 두지 않는다. 코어와 달리 WASM 으로 빌드하지 않으므로 C 의존성이 있어도 된다.
- **플랫폼 선택은 한 곳**: `apps/web/src/main.ts` 의 `createPlatform()` 만 실행 환경을 확인한다. 그 밖의 화면 코드는 `capabilities` 만 본다.
- **빌드**: `apps/desktop` 에서 `npm.cmd run build:exe`(실행 파일만) 또는 `npm.cmd run build`(설치 파일 포함). 결과물은 `target/release/beep-desktop.exe`.
- **빌드 도구**: 이 PC 에는 Visual Studio 가 없어 GNU 도구 모음(`stable-x86_64-pc-windows-gnu` + MinGW)으로 빌드한다.
- **대상 OS**: 지금은 Windows 만. 다른 OS 는 TTS 어댑터가 "지원하지 않음"을 돌려준다.

### 4.4 공용 절차와 MCP (2026-11-13 구현)
- **음원 하나를 만드는 순서는 한 곳에**: `beep_native::job::run` 이 "음악 가져오기 → 가수·곡 찾기 → 안내 음성 만들기 → 코어 호출 → 파일 이름 짓기"를 맡는다. CLI·데스크톱 앱·MCP 는 이것만 부른다. 새 입력 방식이나 엔진을 추가할 때 여기만 고친다.
- **MCP 는 로컬 실행형(stdio)**: `beep-gen mcp`. 서버를 따로 두지 않는다(GitHub 만으로 운영한다는 조건). 구현은 `crates/beep-cli/src/mcp.rs` 이며 외부 MCP 라이브러리 없이 JSON-RPC 를 직접 처리한다.
- **도구 입력 명세는 코어에서 파생**: `create_track` 의 입력 항목은 `param_specs()` 로 만든다. 코어에 파라미터를 추가하면 CLI·화면·MCP 에 함께 나타난다.
- **MCP 가 파일을 쓸 때의 안전장치**: `output` 은 절대 경로(파일 또는 이미 있는 폴더)만 받고, 이미 있는 파일은 `overwrite: true` 가 없으면 덮어쓰지 않는다. 표준 출력에는 프로토콜 메시지만 내보낸다(로그는 표준 오류).

### 4.5 결과 파일 이름과 가수·곡 찾기 (2026-11-14 사용자 확정)
- **이름 형식은 고를 수 있다**(2026-11-15 추가): 목록(`[{n}초] {가수} - {곡}`, `{곡} {n}초`, `{가수} - {곡} {n}초`)에서 고르거나 직접 적는다. 목록과 자리표시자 설명은 코어의 `naming::NAME_FORMATS`·`NAME_FORMAT_HINT` 가 알려준다. 가수를 모르면 `{가수}` 와 그 옆의 구분자를 함께 뺀다. CLI 는 `--name-format`, MCP 는 `name_format`.
- **기본 이름 규칙**: `[{주기}초] {가수} - {곡}.{확장자}`. 음악이 없으면 `[1.4초] beep.mp3`, 곡만 알면 `[1.4초] 곡.mp3`, 곡을 모르면 원래 음악 파일의 이름을 쓴다(`[1.4초] 원래이름.mp3`). 규칙은 코어의 `naming::output_file_name` 한 곳에만 둔다. 파일 이름에 쓸 수 없는 글자(`/ : ? *` 등)는 `_` 로 바꾼다.
- **가수와 곡을 찾는 순서**: (1) 음악 파일의 태그 → (2) `가수 - 곡` 꼴의 파일 이름 → (3) 로컬 AI → (4) 사용자가 직접 입력 → (5) 원래 파일 이름. (1)(2)는 코어(`naming::identify_song`)가 하므로 웹과 로컬이 같다. (3)은 로컬 어댑터(`beep-native::ai`, `song`)만 한다.
- **지어내지 않는다**: 찾지 못하면 빈 값으로 둔다. 사이트 이름(`y2mate.com - ...`)이나 꼬리표(`Official Video`)가 섞인 이름은 (2)에서 받아들이지 않고 다음 단계로 넘긴다.
- **로컬 AI 는 Ollama**: 이 컴퓨터의 Ollama(`http://127.0.0.1:11434`, 환경 변수 `OLLAMA_HOST` 로 변경)에 **파일 이름만** 보낸다. 음악 내용이나 다른 정보는 보내지 않으며, 다른 온라인 AI 서비스는 쓰지 않는다. 모델은 설치된 것 중 첫 번째(환경 변수 `BEEP_GEN_AI_MODEL` 로 지정 가능). Ollama 가 없거나 꺼져 있으면 조용히 다음 단계로 넘어간다.
- **AI 의 답은 검증하고 표시한다**: 제목이 파일 이름에 실제로 들어 있지 않으면 버린다(없는 제목을 지어낸 경우). 받아들인 답은 "로컬 AI 가 추정했다, 틀릴 수 있다"고 사용자에게 알린다(화면의 안내 문구, CLI 의 주의 문구).
- **환경별 동작**: 화면(웹·로컬앱)은 음악을 고르면 찾아서 가수·곡 칸에 채우고, 사용자가 고칠 수 있다. 음원을 만들 때는 그 칸의 값만 쓴다. CLI 는 `--artist`·`--title` 이 없으면 찾고(`--no-ai` 로 AI 제외), `-o` 를 주면 찾지 않는다. MCP 는 `output` 에 폴더를 주면 이름을 자동으로 짓고, 부르는 쪽이 AI 이므로 로컬 AI 에는 묻지 않는다.
- **웹은 로컬 AI 를 쓰지 않는다**: 브라우저 보안 정책상 사용자가 Ollama 설정을 따로 바꿔야 해서 넣지 않았다.

### 4.6 숫자 입력 칸의 증감 단위 (2026-11-14 사용자 확정)
- 화살표(방향키·칸의 위아래 단추)는 코어 명세의 `step` 만큼 움직인다(기본 주기는 0.1초). 직접 적을 때는 단위와 무관한 값(예: 1.25)도 받는다.
- 이를 위해 소수 칸은 `min` 속성을 두지 않고 제출할 때 직접 검사한다(`main.ts` 의 `createField`·`readParams`). `step="any"` 로 되돌리면 화살표가 1씩 움직이게 되므로 바꾸지 않는다.

### 4.7 미리듣기 (2026-11-15 사용자 확정)
- 음원을 만들기 전에 지금 설정으로 **10초**만 만들어 들려준다. 비프와 음악의 크기, 박자를 확인하는 용도다.
- 코어의 `TrackInputs.excerpt`(`Excerpt { seconds, from_percent }`)가 맡는다. 화면·CLI(`--preview`, `--preview-from`)·로컬앱이 같은 기능을 쓴다. 기본값(10초, 30% 지점)은 코어의 `describe()` 가 알려준다.
- 음악이 있으면 고른 위치에서 가장 가까운 **강한 비프**에서 시작한다. 그 구간의 원곡만 변환하므로 전체를 만드는 것보다 빠르다(박자 분석은 곡 전체에 대해 한다). 음악이 없으면 맨 앞을 들려준다.
- 미리듣기에는 안내 음성을 넣지 않고, 가수·곡도 찾지 않는다. 로컬앱은 미리듣기 결과를 완성한 음원과 따로 보관한다(저장할 음원을 덮지 않게).

### 4.8 음량: dB 슬라이더와 자석 지점 (2026-11-15 사용자 확정)
- **음악은 가장 큰 순간이 최대 크기가 되도록 맞춘 뒤 음량을 곱한다.** 작게 녹음된 곡도 음량 100% 에서 같은 크기로 나온다(자동으로 최대값을 찾아 맞춤).
- **화면에서는 음량을 dB 슬라이더로 보여준다(-40 ~ +10 dB).** 코어의 파라미터는 여전히 %(CLI·MCP 와 같음, 0~500)이고, 명세의 `level`(100% 일 때의 dB, 맨 아래·맨 위 dB)을 보고 화면이 바꿔 보여준다. 0 dB(100%)를 넘기면 그만큼 더 키운다. 음악과 비프를 더한 크기가 최대를 넘으면 둘을 같은 비율로 줄이므로 소리가 찌그러지지 않는다(그래서 0 dB 를 넘는 값은 상대 쪽보다 얼마나 더 크게 할지를 뜻한다). 비프의 dB 는 평균 크기 기준이다(사인파라 최대 진폭보다 3 dB 낮다). 음악의 평균 크기와 같은 잣대로 견주기 위해서다.
- **자석 지점**: 음악을 고르면 곡의 크기를 재서(`levels.rs`) 비프 슬라이더 위에 세 지점을 점으로 표시한다. 최대(곡에서 가장 큰 순간), 평균(무음을 뺀 평균 세기, 적정), 최빈(곡이 가장 오래 머무는 크기). 끌어서 움직일 때 1 dB 안에서 달라붙고, 점을 누르면 바로 옮긴다. 자석 지점 위에 있을 때만 그 아래에 설명 줄이 나온다. 방향키로는 달라붙지 않는다(0.5 dB 씩 자유롭게). 슬라이더 옆의 칸에 dB 값을 직접 적을 수도 있다.
- **음량은 마지막에 쓴 값을 그대로 둔다**(2026-11-15 사용자 확정). 음악을 새로 골라도 자동으로 바꾸지 않는다. 곡에 맞춘 값(음악 0 dB, 비프는 곡의 평균 크기)은 초기화 버튼을 누르거나 자석 점을 누를 때만 적용한다. 음악 음량을 낮추면 자석 지점도 함께 내려간다.

### 4.9 음악 파일에 곡 정보 저장 (2026-11-15 사용자 확정)
- **목적**: 가수와 곡을 한 번 알아냈으면 음악 파일에 적어 두어, 다음에 불러올 때 다시 찾지 않게 한다. 파일 이름도 `가수 - 곡` 으로 바꾼다.
- **사용자가 버튼을 눌렀을 때만 원본을 고친다.** 자동으로 고치지 않는다(음원을 만들 때도 고치지 않는다). 화면의 저장 아이콘 버튼("파일명 갱신" 을 끄면 이름은 그대로 둔다), CLI 의 `beep-gen tag`, MCP 의 `save_song_info` 가 같은 코드(`beep-native::tags`)를 쓴다.
- **적는 항목**: 곡 제목·가수·작곡자(각 형식의 표준 자리), 원래 파일 이름(표준 자리, 처음 한 번만), 출처 링크와 AI 활용 여부(설명에 `SOURCE_URL=...`, `AI_GENERATED=Yes|No` 한 줄씩), 분석한 박자 계열과 템포(설명에 `METER=2|3`, `BPM=65.3` 한 줄씩. 템포는 표준 자리에도 정수로).
- **박자와 템포**(2026-11-15 사용자 확정): 곡을 불러오면 바로 분석해(`music::analyze_tempo`, 음량 안내와 함께 온다) 배경음 구역에 박자 계열과 템포를 보여준다. 박자는 선택 상자(자동 / 2박 계열 / 3박 계열)라 분석이 틀렸으면 고칠 수 있다. 저장 아이콘을 누르면 지금의 박자 계열과 그 계열에서의 템포를 함께 적고, 다음에 그 파일을 불러올 때는 적힌 박자 계열을 쓴다. 박자는 곡마다 다르므로 지난번 입력값으로 기억하지 않는다.
- **안전장치**: 사본에 먼저 적고 다시 읽히는지 확인한 뒤 원본과 바꾼다. 같은 이름의 다른 파일이 있으면 덮어쓰지 않고 그만둔다. 비워 둔 항목은 파일에 이미 적힌 값을 그대로 둔다.
- **정보의 출처**: 사용자가 직접 적거나, AI 도구가 MCP 로 넣는다. 프로그램이 유튜브 같은 사이트에 직접 접속해 찾지 않는다(4.2절의 스트리밍 정책과 같은 이유, 그리고 사이트 구조가 바뀌면 깨진다).
- **웹에서는 제공하지 않는다**(브라우저는 원본 파일을 고칠 수 없다). 로컬앱은 원본의 위치를 알아야 하므로 파일 고르기 창(`pick_music`)으로 음악을 고른다. 화면 코드는 `capabilities.songTags` 만 본다.

### 4.10 화면 배치와 저장 위치 (2026-11-15 사용자 확정)
- **구역 네 개, 각각 접을 수 있다**: 비프 → 배경음 → 시작음 → 생성. 접어 둔 상태는 기억한다. 항목을 어느 구역에 둘지는 `main.ts` 의 `PARAM_PLACE` 가 정한다(항목의 이름·범위·기본값은 여전히 코어의 명세에서 온다).
- **줄은 표처럼 맞춘다**: 왼쪽 제목, 가운데 값, 오른쪽 단위. 설명 줄은 모든 칸을 합쳐 쓴다. 항목 설명은 제목과 입력 칸의 풍선 도움말로 둔다.
- **아이콘**: `index.html` 맨 위의 아이콘 모음(`<symbol>`)에 선으로만 그린 아이콘을 두고 `.icon` 한 가지 모양(굵기 1.75)으로 쓴다. 채워진 아이콘이나 그림 글자(이모지)를 섞지 않는다.
- **배경음**: 처음에는 파일·URL 아이콘 버튼만 보인다. 고른 뒤에는 그 자리가 배경음 이름(읽기 전용)과 다시 고르기 버튼, 가수·곡명·작곡자·링크·AI 활용·파일명 갱신, 음량으로 바뀐다.
- **값이 들어간 모습으로 보여주는 선택지**: 파일명과 시작음 문구는 형식(`[{n}초] {가수} - {곡}`)이 아니라 지금 설정에서의 결과(`[1.4초] Foyage - Come a Little Closer`)를 보여준다. 직접 입력을 고르면 형식을 적는다. 실제 이름은 코어가 짓는다.
- **업데이트 버튼(로컬앱, 2026-11-15 사용자 확정)**: 화면 위쪽 버전 표기 옆에 둔다. 지금 실행 중인 것보다 새로운 개발 빌드가 옆 폴더에 있으면 켜지고(`target/release` 에서 실행 중이면 `target/verify/release`, 그 반대도 같다), 누르면 실행 파일을 바꾸고 앱을 다시 시작한다. 인터넷은 쓰지 않는다(`update.rs`, `capabilities.updates`). 앱이 켜져 있어 덮어쓸 수 없을 때 새 빌드는 `target/verify` 에 만든다. GitHub 릴리즈로 받는 정식 업데이트는 배포 절차를 정한 뒤 따로 넣는다.
- **창이 있던 자리 기억(로컬앱, 2026-11-15 사용자 확정)**: 창의 위치·크기와 Windows 가상 데스크톱을 기억해 두고 다음에 그 자리에서 연다(`window_state.rs`). 업데이트로 다시 시작할 때도 같다.
- **저장한 폴더 열기(로컬앱)**: 결과 구역의 저장 버튼 옆 폴더 아이콘은 방금 저장한 파일이 있는 폴더를 파일 탐색기로 연다. 저장한 뒤에만 보인다.
- **저장 위치(로컬앱)**: "만들기" 를 누르면 고른 폴더에 바로 저장한다. 선택지는 배경음 위치/output(처음 기본값), 배경음 위치, 지난번 위치, 다운로드, 내 음악, 폴더 고르기(배경음 파일의 폴더에서 시작). 배경음의 위치를 모르면(주소로 넣었거나 음악이 없으면) 다운로드 폴더에 저장한다. 같은 이름의 파일이 있으면 덮어쓸지 묻는다. 웹은 폴더를 정할 수 없으므로 결과 구역의 "파일 저장" 으로 내려받는다(`capabilities.saveFolders`).
- **글자 칸에서 Enter 로는 만들지 않는다.** 만들기는 버튼으로만 한다(저장까지 이어지므로).
- **입력값 기억과 초기화**(2026-11-15 사용자 확정): 마지막으로 음원을 만들 때의 입력값을 기억해 다음에 그대로 보여준다(음량 포함, 박자 제외). 화면 위쪽 업데이트 버튼 옆의 초기화 버튼이 모든 입력값을 처음 값으로 되돌리고 기억해 둔 값도 지운다. 고른 음악은 그대로 둔다.

## 5. 오디오 생성 정책
- **기본 포맷**: MP3 (Default), WAV 선택 지원.
- **오프라인 동작 보장**: 외부 서버 없이 로컬(브라우저 또는 PC)에서 합성·변환한다. 온라인 TTS 엔진은 선택 사항이다.
- **파라미터 체계**:
  - `n` (기본 주기, 초, default: 1)
  - `m` (비트 분할 수, 정수, default: 2)
  - Weak Beep Volume (`m` 분할음 볼륨 비율, default: 35%, 0~100% 범위)
  - TTS Intro Message (default: "{n}초, {n}초 비프")
  - Length `l` (비프음 지속 시간, TTS 제외, default: 300초)
