# Project Architecture & Policy (beep-gen)

## 1. 프로젝트 개요
- **목적**: 사용자가 지정한 주기(n초), 비트 분할(m개), 약한 비프 볼륨 비율, 전체 길이(l초), TTS 인트로 안내를 포함하는 맞춤형 비프음 오디오 생성기. 향후 음악 파일의 템포를 비프에 맞춰 변환하는 기능을 포함한다.
- **대상 환경**: 웹(GitHub Pages, PWA) + PC 로컬앱(Tauri 2) + CLI·로컬 MCP. 모바일은 PWA만 지원하며 스토어 앱은 만들지 않는다.
- **현행(레거시)**: Python 3.12 + PyQt6 + FFmpeg (`main.py`, `gui.py`, `generator.py`, `tts_engine.py`). Rust 버전이 동일 기능에 도달할 때까지 유지하며, 제거 여부는 그때 사용자에게 확인한다.

## 2. 멀티 플랫폼 아키텍처 (2026-11-13 사용자 확정)

### 2.1 원칙: UI 1벌, 코어 1벌, 환경별 어댑터만 교체
- **코어(Rust)**: 비프 합성, 디코딩, 박자 분석, 템포 변환, 이어 붙이기, MP3/WAV 인코딩을 모두 담는다. 웹은 WASM, 로컬은 네이티브로 같은 코드를 컴파일한다.
- **UI(TypeScript)**: 화면 코드는 하나이며 웹과 로컬앱이 공유한다.
- **어댑터**: 환경마다 달라지는 것은 음성 합성(TTS), 음악 입력(파일/URL), 결과 저장뿐이다.

### 2.2 강제 규칙
1. **코어에 플랫폼 코드 금지**: 코어는 파일·네트워크·시계·OS 호출을 직접 쓰지 않는다. CI에서 코어를 항상 `wasm32-unknown-unknown`으로도 빌드해 검증한다.
2. **어댑터에 계산 로직 금지**: 어댑터는 가져오기·내보내기·OS 호출만 한다. 오디오 샘플을 건드리는 코드는 반드시 코어에 둔다.
3. **UI는 기능 지원 여부로 분기**: "데스크톱이면"이 아니라 "TTS를 지원하면"으로 판단한다. 환경 이름으로 분기하지 않는다.
4. **파라미터 정의는 코어 한 곳**: `n`, `m`, 볼륨, 길이 등의 이름·기본값·범위는 코어의 구조체 하나에 정의하고 UI 타입, CLI 옵션, MCP 도구 스키마는 거기서 파생한다.
5. **C/C++ 의존성 금지**: WASM 빌드를 깨뜨리므로 순수 Rust 라이브러리만 쓴다. 시스템 FFmpeg에도 의존하지 않는다.
6. **웹·로컬 결과 검증은 특성 비교로**: 템포 변환 결과는 양쪽이 샘플 단위로 일치하지 않으므로(검증에서 확인) 길이·박 위치·검출 BPM 같은 특성으로 비교한다.

### 2.3 사용 라이브러리 (모두 순수 Rust)
- 템포 변환 + 박자 분석: `timestretch` (MIT). 0.x 버전이라 올릴 때 API 변경을 확인한다.
- MP3 인코딩: `rusty_mp3` (Apache-2.0)
- 음악 디코딩(MP3·WAV·FLAC·OGG·M4A): `symphonia` (MPL-2.0)
- 수학 함수: `libm`. 웹과 로컬의 결과가 달라지지 않도록 표준 `sin`/`cos` 대신 쓴다.

### 2.4 배경 음악 정책 (2026-11-13 사용자 확정)
- **비프와 음악은 겹친다.** 비프 음량(`beep-volume`)과 음악 음량(`music-volume`)을 각각 0~100%로 조절한다. 비프 음량 0이면 템포만 맞춘 음악이 된다.
- **음원 길이는 음악 길이를 따른다.** 길이(`length`)는 음악이 없을 때만 쓴다. 음악을 자르거나 반복하지 않는다.
- **음악의 앞부분을 자르지 않는다.** 비프 격자를 음악의 기준 박(마디 시작, 불확실하면 첫 박)에 맞춰 옮긴다.
- **두 소리의 최대 진폭 합이 1을 넘으면 넘는 만큼 둘 다 줄인다**(찌그러짐 방지).
- **템포 변환 폭은 제한하지 않고 경고한다.** 한 박을 비프 간격의 0.5·1·2배 중 가장 가까운 쪽에 맞추므로 변화는 최대 약 ±41%이며, 15%를 넘으면 음질 저하를 경고한다.
- 박자를 찾지 못한 곡은 오류로 거절한다. 템포가 변하는 곡은 경고만 한다.

### 2.5 박자 정렬 규칙 (검증에서 도출)
- 박 간격은 대표 BPM이 아니라 모든 박 위치에 대한 직선 맞춤으로 구한다.
- 변환 라이브러리가 배율을 반올림하므로, 실제 적용 배율을 읽어 남은 차이를 미세 재샘플링으로 보정한다.
- 템포 변환·재샘플링·합치기·인코딩은 구간 단위로 이어서 처리한다. 변환된 음악 전체를 메모리에 쌓지 않는다(5분 곡 기준 WASM 메모리 약 170MB).
- 정렬 확인: `crates/beep-core/tests/music_alignment.rs`(자동), `tools/check_align.py`(수동 측정).

## 3. 웹 UI 정책 (2026-11-13 사용자 확정)
- **CSS 스타일링 아키텍처**: 단일 중앙 집중형 CSS(`src/styles/app.css`). 컴포넌트별 CSS, CSS Modules, Tailwind는 쓰지 않는다.
- **이원화 버전 관리 및 캐시 버스팅**: 적용.
  - 빌드 태그 `YYYYMMDDvN`: `version.ts`에 두고, 웹에 반영되는 변경을 할 때마다 자동 갱신한다(같은 날 재변경 시 N 증가).
  - 정식 버전(SemVer): 사용자 승인 후에만 올린다.
- **호스팅**: GitHub Pages만 사용한다. 서버를 두지 않으며 모든 처리는 브라우저 안에서 한다.

### 3.1 웹 UI 구조와 빌드 (2026-11-13 구현)
- **위치**: 화면 코드는 `apps/web/`, 빌드 결과물은 저장소 루트 `dist/` (git 제외). `C:\git\open-test-server.bat` 가 `dist/index.html` 을 찾기 때문이다.
- **빌드 명령**: `apps/web` 에서 `npm.cmd run build` (WASM 생성 → 타입 검사 → 번들). 커밋 전 이 명령과 `cargo test --workspace --all-features` 가 모두 통과해야 한다.
- **경로는 상대 경로**: `vite.config.ts` 의 `base: "./"`. GitHub Pages(`/beep-gen/`)와 로컬 테스트 서버(`/beep-gen/`, `/beep-gen@브랜치/`)에서 같은 결과물이 동작해야 한다. 절대 경로(`/assets/...`)를 쓰지 않는다.
- **프레임워크 없음**: TypeScript + Vite 만 쓴다. 화면이 여러 개로 늘어나면 그때 사용자와 상의한다.
- **입력 폼은 코어의 명세로 생성**: 파라미터별 화면 코드를 따로 쓰지 않는다. 코어의 `param_specs()` 가 이름·기본값·범위를 알려주고 `main.ts` 가 그대로 그린다.
- **플랫폼 인터페이스**: 화면은 `src/platform.ts` 의 `Platform` 만 호출한다. 웹 구현은 `platform-web.ts`(워커 + WASM). 로컬앱은 같은 인터페이스의 다른 구현을 추가한다.
- **WASM 바인딩 생성**: `cargo run -p xtask -- wasm`. `crates/beep-wasm` 의 `wasm-bindgen` 과 `xtask` 의 `wasm-bindgen-cli-support` 는 반드시 같은 버전으로 고정한다. 생성물 `apps/web/src/wasm/` 은 git 에 올리지 않는다.
- **버전 파일**: `apps/web/src/version.ts`. `BUILD_TAG` 는 서비스 워커의 캐시 이름이며, `APP_VERSION` 이 Cargo 작업 공간 버전과 다르면 빌드가 실패한다.
- **PWA**: `public/sw.js` 가 빌드 때 만들어지는 `precache.json` 의 파일을 미리 캐시한다. `dist/` 를 통째로 비우지 않는다(`BeepGen.exe` 가 함께 있을 수 있음).

## 4. 로컬 기능 정책 (2026-11-13 사용자 확정)

### 4.1 TTS (시작 안내 음성)
- **로컬앱·CLI**: Windows 내장 음성만 쓴다(인터넷 불필요). Edge-TTS 등 온라인 엔진은 넣지 않는다. 다른 엔진을 추가할 때는 `beep-native::tts` 의 세 함수(`is_supported`, `list_voices`, `synthesize`) 모양을 유지한다.
- **웹**: 기본은 TTS 비활성 + 로컬앱 안내. 추가로, 원하는 사용자가 브라우저 내장 TTS 모델을 내려받아 쓸 수 있는 선택지를 제공한다(한국어 품질·용량은 구현 단계에서 검증, 미구현).
- **음성을 만드는 일은 코어 밖**: 어댑터가 음성 파일(WAV)을 만들고, 코어는 그것을 받아 맨 앞에 넣은 뒤 0.5초 쉬고 비프를 시작한다. 문구의 `{n}`, `{m}`, `{l}` 치환은 코어의 `intro_text` 가 한다.
- **TTS 가 실패해도 음원은 만든다.** 대신 그 사실을 사용자에게 알린다(CLI 는 주의 문구, 앱은 결과 화면).

### 4.2 URL 로 음악 가져오기
- **오디오 파일의 직접 주소만 받는다**(예: `https://.../song.mp3`). 최대 200MB, 120초 제한.
- **YouTube 등 스트리밍 서비스 주소는 지원하지 않는다.** 저작권 문제 때문이며, 그런 주소가 들어오면 "필요하면 프로젝트를 포크해 직접 추가해 사용하라"는 안내와 함께 거절한다. 스트리밍 추출 기능을 이 저장소에 넣지 않는다.
- 웹에서는 브라우저 보안 정책(CORS) 때문에 제공하지 않는다. 로컬앱과 CLI 에서만 된다.

### 4.3 데스크톱 앱 구조 (2026-11-13 구현)
- **위치**: `apps/desktop/src-tauri` (Tauri 2). 화면은 `apps/web` 의 빌드 결과물(`dist/`)을 그대로 담는다. 화면 코드를 따로 두지 않는다.
- **로컬 어댑터**: `crates/beep-native` (TTS, URL 다운로드). CLI·데스크톱 앱·MCP 가 함께 쓴다. 여기에도 오디오 계산은 두지 않는다. 코어와 달리 WASM 으로 빌드하지 않으므로 C 의존성이 있어도 된다.
- **플랫폼 선택은 한 곳**: `apps/web/src/main.ts` 의 `createPlatform()` 만 실행 환경을 확인한다. 그 밖의 화면 코드는 `capabilities` 만 본다.
- **빌드**: `apps/desktop` 에서 `npm.cmd run build:exe`(실행 파일만) 또는 `npm.cmd run build`(설치 파일 포함). 결과물은 `target/release/beep-desktop.exe`.
- **빌드 도구**: 이 PC 에는 Visual Studio 가 없어 GNU 도구 모음(`stable-x86_64-pc-windows-gnu` + MinGW)으로 빌드한다.
- **대상 OS**: 지금은 Windows 만. 다른 OS 는 TTS 어댑터가 "지원하지 않음"을 돌려준다.

## 5. 오디오 생성 정책
- **기본 포맷**: MP3 (Default), WAV 선택 지원.
- **오프라인 동작 보장**: 외부 서버 없이 로컬(브라우저 또는 PC)에서 합성·변환한다. 온라인 TTS 엔진은 선택 사항이다.
- **파라미터 체계**:
  - `n` (기본 주기, 초, default: 1)
  - `m` (비트 분할 수, 정수, default: 2)
  - Weak Beep Volume (`m` 분할음 볼륨 비율, default: 35%, 0~100% 범위)
  - TTS Intro Message (default: "{n}초, {n}초 비프")
  - Length `l` (비프음 지속 시간, TTS 제외, default: 300초)
